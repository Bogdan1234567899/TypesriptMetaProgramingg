# Task 4 — Boundary Rules

Правила редагування файлів у проєкті з codegen. Прив'язані до конкретної структури з `project_tree.md`.

## Можна редагувати руками

| Файл/папка | Чому можна |
|---|---|
| `models/*.json` | Це джерело правди — DSL-моделі. Зміни тут спричиняють регенерацію. |
| `codegen/Codegen.cs`, `codegen/TestCodegen.cs` | Це самі генератори. Змінюються коли потрібно нове правило генерації. |
| `runtime/*.cs` | Ручний бізнес-шар. Може викликати generated runtime, але не залежить від його внутрішньої реалізації. |
| `reports/*.md`, `README.md` | Документація. |
| `example_files/handwritten_*.cs` | Приклади ручних розширень для документації. |

## Не можна редагувати руками

| Файл/папка | Чому ні |
|---|---|
| `generated/*.cs` | Перезаписується при кожному запуску codegen — твої зміни зникнуть. |
| Будь-який файл з префіксом `Generated` | Конвенція: префікс = власність генератора. |
| Будь-який файл з коментарем `// AUTO-GENERATED` у першому рядку | Маркер генерації — не редагувати. |

## Приклади

**Правильно:** додати нову подію у `models/payment_retry_fsm.json` → запустити codegen → перевірити що `generated/GeneratedPaymentRuntime.cs` оновився.

**Правильно:** додати в `runtime/PaymentService.cs` логування або retry-логіку поверх виклику `GeneratedPaymentRuntime.Next(...)`.

**Неправильно:** відкрити `generated/GeneratedPaymentRuntime.cs` і дописати transition вручну. Наступний запуск codegen знищить зміну, і ніхто не зрозуміє чому система перестала працювати.

**Неправильно:** скопіювати код з `generated/` у `runtime/` і змінювати там. Тоді треба пам'ятати про дві версії — і вони неминуче розсинхронізуються.

## Що робити якщо потрібен новий transition?

1. Відкрити відповідний `models/*.json`.
2. Додати запис у `transitions`. Якщо подія нова — додати до `events`.
3. Запустити codegen — `dotnet run --project codegen`.
4. Перевірити diff у `generated/` (це і є regeneration_report).
5. Якщо потрібна бізнес-логіка на новий transition — додати у `runtime/`.

## Як технічно захистити generated файли

Можна додати у CI перевірку: запустити codegen, порівняти `git diff` — якщо є зміни у `generated/`, які не співпадають з тим, що було б при чистій регенерації, fail build. Тоді ручні правки у `generated/` неможливо комітнути.
